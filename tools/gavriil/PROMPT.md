Додай у цього бота (Гавриїл, мій особистий Telegram-бот) функцію: додавати, закривати й показувати збори на моєму сайті taras.kyiv.ua.

## Як це влаштовано (сайт уже готовий — бот лише пересилає команду)

Сайт — GitHub Pages у репозиторії `trs-hash/Films`. Там є GitHub Actions workflow `fundraiser.yml` («Збір із бота»), який сам розбирає текст команди, змінює сайт і відписує результат у Telegram. Боту треба зробити ОДИН запит до GitHub API:

```
POST https://api.github.com/repos/trs-hash/Films/actions/workflows/fundraiser.yml/dispatches
Authorization: Bearer $FILMS_GITHUB_TOKEN
Accept: application/vnd.github+json
X-GitHub-Api-Version: 2022-11-28
Content-Type: application/json

{"ref": "main", "inputs": {"text": "<повний текст повідомлення, разом із /командою>", "chat_id": "<id чату, куди відписати>"}}
```

- `204` — прийнято. Одразу відповісти в чат: «⏳ Прийняв. За хвилину відпишу, що вийшло.» Результат («✅ Збір … додано — посилання, сума» або «❌ що не так») надішле в цей самий чат сам workflow — через секрет `TG_BOT_TOKEN` у репозиторії Films (це токен цього бота). Боту чекати чи опитувати нічого не треба.
- Помилки — відповісти людською мовою: `401` токен недійсний або прострочений; `403` токену бракує дозволу Actions: Read and write; `404` нема доступу до репозиторію або workflow ще не в `main`; `422` workflow не знайдено в `main` чи неправильні inputs; мережа/таймаут — «не достукався до GitHub».
- Усі значення inputs — рядки. Невідомі inputs GitHub відхиляє (422) — не додавай своїх.
- Окрім `text` і `chat_id`, workflow приймає й окремі поля (теж рядки, всі необовʼязкові): `action` (add | close | list), `url` (посилання на банку monobank), `title`, `about`, `goal` (гривні), `until` (31.12 або 2026-12-31), `kind` (charity | channel). Якщо передано `action`, він важливіший за команду в тексті.

## Команди (бот нічого не розбирає — пересилає текст як є)

- `/zbir https://send.monobank.ua/jar/…` — додати збір: назву, опис і ціль workflow бере з самої банки. Можна з власними даними — назва другим рядком, далі опис, і за бажання «ціль 50000, до 31.12, благодійний». Повторна та сама банка — оновлення, не дубль.
- `/zakryty [якір | посилання | частина назви]` — закрити збір (без уточнення — єдиний відкритий; якщо їх кілька, workflow перепитає).
- `/zbory` — що зараз на сайті і скільки зібрано.

Підтримай і форму з іменем бота (`/zbir@ІмʼяБота`). Багаторядковий текст пересилай повністю, обріж до 4000 символів.

## Безпека — обовʼязково

- Команди приймаються ЛИШЕ від власника: Telegram user id зі змінної `FILMS_OWNER_IDS` (кілька — через кому). Від інших — мовчки ігнорувати (не підказувати, що команда існує). Без цього будь-хто, хто напише боту, міг би поставити збір на мій сайт.
- `FILMS_GITHUB_TOKEN` — лише зі змінних середовища / секретів бота. Ніколи не логувати, не показувати в чаті, не комітити. Додай у `.env.example` (або аналог) з порожнім значенням і коментарем.
- Якщо токена нема — бот відповідає «❌ Нема FILMS_GITHUB_TOKEN — бот не може достукатися до сайту» і не падає.

## Що я зроблю руками (допиши в README бота)

- GitHub → Settings → Developer settings → Fine-grained tokens → Generate: Repository access — Only select → `trs-hash/Films`; Permissions → Actions — Read and write (більше нічого). Строк — до року. Покласти в `FILMS_GITHUB_TOKEN`.
- `FILMS_OWNER_IDS` — мій Telegram id (покаже @userinfobot).
- У репозиторії Films: Settings → Secrets and variables → Actions → секрет `TG_BOT_TOKEN` = токен цього бота (щоб workflow відписував результат).
- Перевірка без бота: Films → Actions → «Збір із бота» → Run workflow (ті самі поля).

Готово, коли: я пишу боту `/zbir https://send.monobank.ua/jar/…`, бот одразу відповідає «⏳ Прийняв…», а за хвилину-дві приходить «✅ Збір … додано» з посиланням; від чужого акаунта бот мовчить; тести проходять.
