## Що вже готово (сайт і репозиторій `trs-hash/Films`) — нічого там не змінюй

  і показує людині статус: «✓ Ви записані», «✓ Місце заброньовано · оплата на місці», «Чекаємо оплату» → сторінка
  monobank → «✓ Оплачено». Що саме відповідати — розписано нижче до поля; сайт уже протестовано з підставним сервером.
- Події живуть у `seasons.json` → `meetings` у репозиторії. Змінює їх GitHub Actions workflow **«Зустріч із бота»**

- Готові шматки для бота: `tools/gavriil/films-zustrichi.mjs` (Node 18+) і `tools/gavriil/films_zustrichi.py` (Python) —
  функція, що пересилає команду в GitHub. Можеш взяти як є або переписати в стилі бота.
- Репозиторій публічний: `git clone https://github.com/trs-hash/Films.git` у тимчасову папку, щоб усе це прочитати.

Твоя частина — **на сервері бота**: (А) пересилати команди керування подіями, (Б) API реєстрації для сайту,
(В) оплата monobank (вимкнена до ФОП), (Г) команди для мене про записи, (Ґ) за бажання — запис прямо в Telegram.

## А. Керування подіями з Telegram (як зі зборами)

Бот нічого не розбирає — пересилає текст у GitHub одним запитом (той самий `FILMS_GITHUB_TOKEN`, що й для зборів):

```
POST https://api.github.com/repos/trs-hash/Films/actions/workflows/meeting.yml/dispatches
Authorization: Bearer $FILMS_GITHUB_TOKEN
Accept: application/vnd.github+json
X-GitHub-Api-Version: 2022-11-28

{"ref": "main", "inputs": {"text": "<повний текст повідомлення з /командою>", "chat_id": "<id чату>"}}
```

`204` — одразу відповісти «⏳ Прийняв. За хвилину відпишу, що вийшло.» Результат («✅ …» / «❌ …») надішле в цей чат
сам workflow (секрет `TG_BOT_TOKEN` у репозиторії вже є — той самий, що для зборів). Помилки 401/403/404/422/таймаут —
людською мовою, як у зборах. Окрім `text`, workflow приймає `action` (add | list | cancel | restore | remove | payments | config)
і `data` — JSON-рядок із полями (для режиму асистента, див. нижче). Усі значення inputs — рядки.

Команди (лише від мене):
- `/zustrich` — додати або змінити подію; поля рядками «ключ: значення»:
  ```
  /zustrich
  дата: 14.11 19:00–21:00
  назва: Про звички й волю
  місто: Київ
  місце: Книгарня «Є»
  адреса: вул. Лисенка, 3
  ціна: 300            (або: безкоштовно)
  місць: 40
  опис: Розмова наживо, питання з залу.
  ```
  Ще: `реєстрація: ні` (без реєстрації) або `реєстрація: https://…` (своя форма), `мапа:`, `запис:` (відео після події),
  `у шапці: ні`, `id: kyiv-1411` (змінити саме цю), «-» замість значення — прибрати поле. Зміна без `id` — за датою й містом.
- `/zustrichi` — що на сайті; `/skasuvaty [id | 14.11 | назва]` — скасувати (на сайті «Скасовано»); `/vidnovyty`; `/vydalyty`.
- `/oplata online | onsite` — платні події: карткою через monobank чи на місці (зараз — `onsite`).
- `/zustrichi_nalashtuvannia` з рядками `api: https://…` і `telegram: ІмʼяБота` — підключити сайт до твого API (крок Д).

Після `/skasuvaty` (крім пересилання) покажи мені список записаних на цю подію — щоб я міг їх повідомити, а оплачені —
з пропозицією повернути гроші (В.5).

**Якщо бот — LLM-асистент з інструментами:** додай `add_meeting(date, time?, title?, city?, place?, address?, fee?, capacity?,
about?, register?, id?)` → POST з `action: "add"` і `data` = JSON цих полів; `list_meetings()`, `cancel_meeting(query)`,
`set_payments(mode)`. Модель не вигадує дати й ціни — лише те, що я сказав; якщо чогось бракує (дата, назва) — перепитує.

## Б. API реєстрації для сайту

Сайт ходить на адресу з `seasons.json → meetings.api`, наприклад `https://api.taras.kyiv.ua/zustrichi` (ти запропонуєш,
я налаштую DNS — крок Д). Три запити:

**`GET {api}/state`** — вільні місця й чи відкрита реєстрація (для майбутніх подій):
```json
{"items": {"kyiv-1411": {"left": 12, "open": true}, "lviv-0612": {"left": null, "open": true}}}
```
`left` — ціле ≥ 0 або `null` (місць не обмежено); `open: false` — реєстрацію закрито (мною чи подія минула/скасована).

**`POST {api}/register`** — тіло JSON, але **Content-Type: `text/plain;charset=UTF-8`** (так сайт обходиться без preflight —
читай тіло як JSON незалежно від Content-Type; розмір ≤ 4 КБ):
```json
{"meeting": "kyiv-1411", "name": "Олена", "phone": "+380671234567", "telegram": "olena_k", "count": 2, "comment": "…", "website": ""}
```
- `website` — пастка для ботів (людина не бачить поля): не порожнє → відповісти як на успіх (`{"ok": true, "token": "x",
  "status": "confirmed"}`), але нічого не зберігати й не сповіщати.
- Перевір: `name` 2–80 символів; `phone` — `^\+?\d{9,15}$` (0671234567 → +380671234567); `telegram` — порожньо або
  `^[A-Za-z0-9_]{4,32}$`; `count` 1–5 і не більше вільних місць; `comment` ≤ 500.
- Подія — з `https://taras.kyiv.ua/seasons.json` (`meetings.items`, кеш 60 с, при помилці — остання справна копія).
  Записатися можна, якщо подія є, не `enabled: false`, не `cancelled`, не `register: false`, без `url` (своя форма),
  дата ≥ сьогодні (Київ) і я не закрив реєстрацію. Ціна — `fee` (гривні; нема — безкоштовна), місця — `capacity` (нема — без меж).
- Той самий телефон на ту саму подію, коли запис іще живий, — не дубль: поверни наявний токен і статус.

Відповіді:
- **200** `{"ok": true, "token": "<випадковий, ≥ 24 байти, urlsafe>", "status": "…", "pay_url": "…", "note": "…"}`:
  - безкоштовна → `"status": "confirmed"`;
  - платна, оплата на місці (`meetings.payments` = `onsite` або нема `MONO_ACQ_TOKEN`) → `"booked"`;
    `note` за бажання — одне речення простим текстом (сайт показує як текст, не HTML);
  - платна, онлайн → створити рахунок monobank (В) → `"payment"`, `pay_url` = `pageUrl` рахунку. Сайт сам переведе людину
    на оплату; **сайт пускає лише на `https://pay.mbnk.biz/…`, `https://pay.monobank.ua/…`, `https://send.monobank.ua/…`** —
    якщо monobank дасть інший домен, скажи мені.
- **409** `{"ok": false, "error": "full" | "closed" | "past"}`; **404** `{"ok": false, "error": "unknown"}`;
  **422** `{"ok": false, "error": "invalid", "fields": ["phone"]}`; **429** — забагато спроб (≈ 5 за хвилину з IP, 10 за день на телефон).

**`GET {api}/reg/{token}`** → `{"status": "…", "meeting": "kyiv-1411", "count": 2, "pay_url": "…"}` (pay_url — лише поки
`payment`); невідомий токен — 404. Сайт питає це, коли людина відкриває «Зустрічі» (і кожні 5 с, поки «Чекаємо оплату»),
тож для `payment` перевір рахунок у monobank, якщо остання перевірка була > 10 с тому (на випадок, коли вебхук загубився).

Статуси: `confirmed` (безкоштовна), `booked` (заброньовано, оплата на місці), `payment` (чекаємо оплату), `paid`,
`failed` (оплата не пройшла чи рахунок прострочено — місце звільняється), `cancelled` (скасовано мною або повернення).
Місця займають `confirmed`, `booked`, `paid` і `payment` (поки рахунок живий — validity 30 хв).

CORS: `Access-Control-Allow-Origin: https://taras.kyiv.ua` (лише цей), на `OPTIONS` — 204 з `Access-Control-Allow-Methods:
GET, POST` і `Access-Control-Allow-Headers: Content-Type`. Плюс `GET {api}/health` → 200 (для перевірки).

Зберігання: SQLite у теці даних бота (не в git), файл з правами 600. Таблиця записів: id, token, meeting_id, name, phone,
telegram, count, comment, status, amount, invoice_id, created_at, updated_at. Персональні дані видаляти через 60 днів після
події (щоденне прибирання). У логах телефон маскувати (+38067•••4567), імен і коментарів не писати.

Сповіщення мені в Telegram (FILMS_OWNER_IDS): кожен новий запис («🆕 «Про звички й волю», 14.11 — Олена, +380…, @olena_k,
2 місця · вільно 10»), оплата («💳 Оплачено 600 ₴ — Олена»), невдала оплата, «місць більше нема».

## В. Оплата monobank (інтернет-еквайринг) — підготувати, увімкнути, коли буде ФОП

Документація: https://api.monobank.ua/docs/acquiring.html — **звір із нею кожен запит**; якщо щось у мене тут розходиться
з документацією, роби за документацією й напиши мені, що саме.

1. Токен — змінна `MONO_ACQ_TOKEN` (видає monobank для ФОП у кабінеті еквайрингу). Нема токена → онлайн-оплати нема:
   платні реєстрації отримують `booked` (оплата на місці), а якщо на сайті вже `meetings.payments: online` — попередь мене в Telegram.
2. Рахунок: `POST https://api.monobank.ua/api/merchant/invoice/create`, заголовок `X-Token`, тіло:
   `{"amount": <fee × count × 100, копійки>, "ccy": 980, "merchantPaymInfo": {"reference": "<id запису>", "destination":
   "Квиток: «Назва», 14.11.2026"}, "redirectUrl": "https://taras.kyiv.ua/#z-<id події>", "webHookUrl": "{api}/mono/webhook",
   "validity": 1800, "paymentType": "debit"}` → `invoiceId`, `pageUrl`. Зберегти `invoiceId`, віддати `pageUrl` як `pay_url`.
3. Вебхук `POST {api}/mono/webhook`: перевірити підпис `X-Sign` (base64, ECDSA з SHA-256 над сирим тілом) публічним ключем
   з `GET https://api.monobank.ua/api/merchant/pubkey` (кешувати; якщо підпис не сходиться — один раз оновити ключ). Без
   правильного підпису — 400 і нічого не міняти. `success` → `paid`; `failure`, `expired` → `failed`; `reversed` → `cancelled`.
   Вебхуки можуть приходити не по черзі — не відкочуй новіший стан старішим (`modifiedDate`). Відповідати 200 швидко, ідемпотентно.
4. Перевірка статусу без вебхука: `GET https://api.monobank.ua/api/merchant/invoice/status?invoiceId=…` (див. Б, `/reg/{token}`).
5. Повернення: при `/skasuvaty` чи на мою команду — `POST https://api.monobank.ua/api/merchant/invoice/cancel`
   (`invoiceId`, сума) **лише після мого явного підтвердження** в чаті.
6. Перевір усе з тестовим токеном monobank (якщо видають — див. документацію) до справжнього; у звіті — чим перевірив.

Доки нема ФОП, гроші за квитки автоматично на особисту картку чи банку **не приймай** — це вирішую я. Зараз платні = «на місці».

## Ґ. (Бажано) Запис через Telegram

Якщо в `seasons.json → meetings.telegram` імʼя цього бота, сайт показує «або через Telegram ↗» з посиланням
`https://t.me/<бот>?start=z_<id події>`. На `/start z_<id>` бот питає імʼя, телефон (кнопка «Поділитися номером»), скільки
людей — і робить той самий запис, що й API (спільний код), а для онлайн-оплати надсилає посилання на рахунок. Цим людям бот
може потім написати (нагадування за день, скасування) — лише про цю подію. Мої команди лишаються лише для мене.

## Д. Як відкрити API назовні

Запропонуй варіант під цей сервер: піддомен `api.taras.kyiv.ua` (я додам A-запис у DNS — скажи, яку IP) + Caddy з
автоматичним HTTPS як зворотний проксі на порт бота на 127.0.0.1; або Cloudflare Tunnel, якщо сервер не має білої IP.
Бот слухає лише 127.0.0.1. Коли запрацює — підключи сайт сам: надішли в Telegram (від мене)
`/zustrichi_nalashtuvannia` з рядками `api: https://api.taras.kyiv.ua/zustrichi` і `telegram: <імʼя бота>` — або скажи мені адресу.

Перевірка, як це бачить сайт:
```
curl -i https://api.taras.kyiv.ua/zustrichi/state
curl -i -X POST https://api.taras.kyiv.ua/zustrichi/register -H 'Origin: https://taras.kyiv.ua' \
  -H 'Content-Type: text/plain;charset=UTF-8' \
  --data '{"meeting":"<id майбутньої події>","name":"Тест","phone":"+380671234567","telegram":"","count":1,"comment":"","website":""}'
```
(у відповіді має бути `Access-Control-Allow-Origin: https://taras.kyiv.ua`; тестовий запис потім видали).

## Безпека — обовʼязково

- Команди А і Г — **лише від мене**: Telegram user id з `FILMS_OWNER_IDS`. Від інших — мовчки ігнорувати.
- `FILMS_GITHUB_TOKEN`, `MONO_ACQ_TOKEN` — лише в змінних середовища; ніколи в git, логах чи чаті. Додай у `.env.example`
  з порожніми значеннями й коментарями.

  відлуння сирого вводу. Вебхук monobank — лише з правильним підписом.
- Персональні дані — лише на сервері (ніколи в репозиторій сайту), видалення через 60 днів після події.

Готово, коли: я пишу `/zustrich` з полями — за хвилину-дві подія на сайті; на сайті записуюсь на безкоштовну подію — мені

від чужого акаунта бот мовчить; тести проходять.
