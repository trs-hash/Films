# Теми лекцій (локальна ШІ-модель на сервері)

Сайт показує лекції з YouTube, згруповані за темами. Теми — у `lectures.json` (корінь репозиторію), його формує
`lectures.py` на сервері власника з локальними моделями й комітить сюди. Без цього файлу сайт показує лекції без тем
(«Усі студії» — так розділ зветься на сайті); лекції, яким тему ще не підібрано, — згори «Нові студії».

Встановлення на сервер — `PROMPT.md` (готова підказка для Claude Code на сервері).

## Як народжуються теми

1. **Розшифровка** лекції: власний файл з `inbox_dir` (`<YouTube ID>.mp4` тощо) → субтитри YouTube → звук з YouTube
   і Whisper. Мова — українська. Whisper — той, що вже є на сервері (`whisper_backend` у `config.json`):
   бібліотека `faster-whisper` / `openai-whisper`, будь-яка команда (`command`: whisper.cpp, CLI openai-whisper…)
   чи Whisper-служба по HTTP (`http`: OpenAI-сумісна, whisper.cpp server, whisper-asr-webservice). `auto` — сам
   знайде бібліотеку. Перевірити на своєму файлі: `lectures.py transcribe ФАЙЛ` (текст і швидкість).
2. **Розуміння:** мовна модель (Ollama, напр. `gemma3:12b`) читає розшифровку частинами й пише зміст (2–3 речення),
   5–8 ключових понять і широку галузь.
3. **Відбиток** змісту (embedding, модель `bge-m3`) — щоб рахувати, наскільки лекції схожі.
4. **Теми** (`topics.py`) — широкі, а не по тегу на лекцію:
   - тема зʼявляється, лише коли ≥ 3 лекції схожі між собою; поодинокі чекають («Нові студії» на сайті);
   - нова лекція йде в найближчу тему, якщо дуже схожа; якщо «так собі» — модель вирішує, чи широка тема її охоплює;
   - схожі теми зливаються, тем не більше 12 (числа — `config.json → topics`);
   - назву дає модель: 1–3 слова, широко, «щоб туди лягли й майбутні лекції»; якщо модель назвала нову групу так само,
     як наявну тему, — це та сама тема (без дублів).
5. `lectures.json` + `report.md` → git commit/push (лише коли щось змінилось). Повторно лекцію не обробляє (кеш у `state_dir`).

## Як «навчати» теми (правки власника)

`overrides.json` — найсильніше слово. Сервер застосовує його при кожному запуску (робить `git pull` перед роботою):

| Поле | Що робить |
|---|---|
| `rename: {"zvychky-i-volia": "Звички й воля"}` | назва теми; власні назви стають для моделі зразком ширини й стилю |
| `about: {"id": "Одне речення"}` | опис теми на сайті |
| `lock: ["id"]` | назву не чіпати, з іншими не зливати |
| `merge: [["id1", "id2"]]` | злити (у першу) |
| `pin: {"YouTubeID": "id"}` | лекцію — в цю тему, назавжди |
| `split_off: ["YouTubeID"]` | лекцію — геть із теми (буде серед «Нових», поки не набереться своя тема) |

Як це роблять: власник каже Claude в сесії з цим репозиторієм («злий теми А і Б», «назви тему про звички
"Звички й воля"») — Claude правує `overrides.json` і пороги в `config.example.json`/README, дивлячись на свіжий
`report.md` (там кожна лекція, її тема й схожість). Сервер підхопить на наступному запуску (щогодини).

## Файли

- `lectures.py` — конвеєр (`run`, `run --dry`, `report`, `check`, `transcribe ФАЙЛ`);
- `topics.py` — правила тем (без моделей), `test_topics.py` — їхні тести, `test_e2e.py` — увесь конвеєр із підставними
  YouTube й Ollama, `test_whisper.py` — підключення наявного Whisper (команда, служба) з підставними. Запуск: `python3 -m unittest discover -s tools/lectures -p 'test_*.py'` (і в `node tests/qa.js` — кейс LT01);
- `config.example.json` — зразок налаштувань (`config.json` — лише на сервері, у .gitignore);
- `overrides.json` — правки власника; `report.md` — звіт останнього запуску (пише сервер).
