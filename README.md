# Films — taras.kyiv.ua

Статичний сайт (GitHub Pages, домен у `CNAME`).

## 🎞 Головна — фільми з афішами

Кожне відео — окремий фільм зі своєю афішею. Каталог за датою виходу: роки від найновішого, у році —
найновіші першими. Ні премʼєр, ні відліків, ні нагадувань — лише афіші того, що вже вийшло. Окремого заголовка
над каталогом нема: одразу роки й афіші.

Афіша горизонтальна, як кінокартка, і складається сама з того, що вже є на YouTube:
- **кадр** — превʼю відео цілком, 16:9, нічого не обрізано. Якість — найвища з наявних: maxres 1280×720,
  якщо нема — sddefault 640×480, далі hqdefault (у 4:3 чорні смуги згори й знизу обрізаються рівно по краю).
  Без srcset — браузер не підмінить меншою картинкою. Кадри нижче першого екрана довантажуються при прокрутці;
- **№ у каталозі** — порядковий номер від першого фільму. Нові фільми старих номерів не змінюють;
- **дата виходу**, **назва** вузьким шрифтом афіш (Oswald, лежить у `fonts/`, ліцензія OFL; кегль підбирається
  сам, найдовше слово завжди влазить, хештеги з кінця назви прибрано) і «титри»: «Фільм Тараса Максим’яка · 12 хв».
  Тривалість сайт бере з YouTube (запит `videos.list`, 1 одиниця квоти на 50 відео; що вже відомо — не
  перепитує). Не вийшло — афіша без хвилин;
- «Новий» — на найсвіжішому фільмі перші 14 днів, поки його не переглянуто;
- «Переглянуто» — штамп на кадрі, як у власному каталозі (облік живе в браузері глядача).

Опис відео афіші не потрібен. Відкривається так само, як було: на компʼютері — плеєр на сайті з гортанням
фільмів (‹ ›, ← →, свайп) і «№ 2 із 8»; на телефоні — дотик веде в застосунок YouTube, «⋯» на афіші —
аркуш фільму (кадр, посилання, картка для Stories). Також працюють «з твого візиту — 2 нові фільми ▶ дивитися
підряд», теми з хештегів (`#t=…` показує лише фільми теми) і посилання `#d=РРРР-ММ-ДД` / сторінки `/d/…/`.
На компʼютері — три афіші в ряд, на планшеті — дві, на телефоні — одна на всю ширину.

Поки на каналі нема жодного публічного відео, на місці каталогу — пунктирна афіша «Скоро · № 01» і посилання
на YouTube.

Налаштування — `seasons.json` → `films` (ті самі поля, що й у календаря):

```json
"films": { "enabled": true, "start": "", "playlist": "UURSKTGA5a2hLrai_MXNaoUQ", "exclude": ["PLS50DDpfd-9w"] }
```

- `playlist` — звідки брати фільми (UU… — усі завантаження каналу; посилання на канал сайт перетворить сам);
- `exclude` — плейлисти, чиї відео не показувати (Shorts);
- `start` — не брати відео, старіші за цю дату (порожньо — усі);
- `enabled: false` — сховати фільми (як календар); у `?check` вони лишаються в попередньому перегляді.

**Характер.** Теплий «папір кінопрограмки» замість чисто білого (темна тема — тепла темрява зали), вузький
шрифт афіш для імені, років, номерів і назв, червоний акцент лишився. Контраст сірого тексту ≥ 4.5:1
в обох темах (перевіряє тест).

## ⏸ Календар схований про запас

Щоденний формат відкладено, тож «стіна днів» з усіма функціями лежить у резерві: `seasons.json` →
`"calendar": { "enabled": false, … }`.

- **Подивитися, як виглядає схований календар:** `taras.kyiv.ua/?check` — він там у попередньому перегляді
  з червоною позначкою «Сховано».
- **Повернути:** у `seasons.json` поставити `"enabled": true` (або прибрати цей рядок). Більше нічого: код,
  тести, архів і відмітки «переглянуто» в браузерах глядачів нікуди не ділися.
- **Архів на GitHub** і далі зберігає всі відео (на будь-який формат). Сторінки днів, дні в `sitemap.xml` і великі
  кадри він робить, поки на сайті є фільмотека або календар.
- `"enabled": "ні"`, `"так"` у лапках сайт теж зрозуміє й попросить писати без лапок; незрозуміле значення —
  календар лишається схованим.

## Головна — «стіна днів» (з 30.09.2026; зараз схована)

Коли календар увімкнено, перше, що бачить глядач, — календар щоденних відео. Над ним з'являється каталог тем,
зібраний з хештегів. Сезони — необов'язковий блок під календарем.

| Файл | Що це |
|---|---|
| `index.html` | Головна: фільмотека (афіші) → стіна днів, коли увімкнена → (сезони); у шапці — збори й підтримка, коли увімкнені |
| `seasons.json` | Налаштування: фільмотека, календар, теми, сезони, підтримка — **єдине, що треба редагувати руками** |

| `archive.json` | Архів (фолбек, коли YouTube недоступний). Оновлює GitHub щогодини — див. «Архів без комп'ютера» |
| `d/РРРР-ММ-ДД/` | Сторінки днів із прев'ю для Telegram/Instagram (генерує архів) |

| `404.html` | Неіснуюча адреса → головна; `/d/дата/` → цей день на стіні |
| `manifest.webmanifest`, `icons/`, `sw.js` | Застосунок на головному екрані (PWA) і робота без інтернету |
| `tools/archive.mjs`, `.github/workflows/archive.yml` | Генератор архіву і задача GitHub, що його запускає |
| `tools/fundraisers.mjs` → `fundraisers.json` | Суми зборів із банок monobank (та сама задача; зʼявиться з першим збором) |
| `tools/zbir.mjs`, `.github/workflows/fundraiser.yml`, `tools/gavriil/` | Збір із бота Гавриїла: команда → GitHub → сайт; готові шматки коду для бота |
| `calendar.html` | Архів першої версії календаря (окрема сторінка) |

```json
{
  "calendar": {
    "start": "2026-09-30",
    "playlist": "UURSKTGA5a2hLrai_MXNaoUQ",
    "exclude": ["PLS50DDpfd-9w"]
  },
  "topics": [
    { "tag": "подорожі", "title": "Подорожі", "about": "Дороги, міста, люди.", "aliases": ["подорож"] }
  ],
  "ignore_tags": [],
  "seasons": []
}
```

- Стіна починається з дня **першого опублікованого відео** — без порожніх днів до нього. Поки відео нема,
  на головній спокійне «Скоро тут з'явиться перша стрічка».
- `calendar.start` — нижня межа: відео, опубліковані раніше (проби), на стіну не потрапляють.
- `calendar.playlist` — звідки брати відео. `UU…` — усі завантаження каналу: нічого додавати в плейлисти не треба.
  Поки на каналі нема жодного публічного відео, YouTube цей список не віддає, і це не помилка.
- `calendar.exclude` — плейлисти, чиї відео в календар не йдуть (зараз — «Shorts»).

### Теми з хештегів

Досить написати хештег у назві або описі відео на YouTube, наприклад `#подорожі`. Сайт сам збере каталог:
ряд тем над календарем з кількістю відео. Клік по темі показує всі її відео (найновіші першими),
а в календарі приглушує решту, тож видно, коли тема «жила». Посилання на тему (`taras.kyiv.ua/#t=подорожі`)
можна поширювати. У плеєрі під запискою — теми цього відео.

- Регістр не важливий (`#Подорожі` = `#подорожі`). Числа (`#1`), якорі в посиланнях і `#shorts` темами не є.
- `topics` (необов'язково) — гарна назва, опис і синоніми, щоб `#подорож` і `#подорожі` були однією темою.
- `ignore_tags` — хештеги, які не треба показувати як теми.
- Усі знайдені теми з кількістю видно на `?check`: так легко помітити описки.
- На YouTube перші 3 хештеги з опису показуються над назвою відео. Краще ставити 1–3 хештеги,
  бо понад 60 YouTube ігнорує всі.

### Як відкривається відео

- **Компʼютер:** вікно з плеєром просто на сайті, під ним записка (опис відео) і теми.
  Ctrl/Cmd-клік відкриває відео на YouTube у новій вкладці.
- **Телефон і планшет (iOS, iPadOS, Android):** одразу застосунок YouTube. Якщо застосунку нема,
  відкриється сайт YouTube. На Android це робить intent, на iOS — звичайне посилання youtube.com,
  яке система сама передає застосунку.
- Локальні відео з архіву (режим `doomsday`, `base` + `v`) завжди грають у вікні на сайті: їх нема на YouTube.

### Переглянуте

Відкрите відео одразу позначається: у календарі день закреслюється, у картках з'являється червона смужка.
Позначка ставиться на всіх копіях відео на сторінці і з'являється в інших відкритих вкладках.
Позначки зберігаються в браузері (`localStorage`, ключ `vw`, спільний з `calendar.html`) і лишаються
між візитами. Сайт також просить браузер не стирати це сховище, коли бракує місця.

Обмеження: позначки прив'язані до браузера й пристрою, акаунтів нема. Safari стирає дані сайтів,
які людина не відкривала понад 7 днів користування браузером. Тому хто повертається рідше, може
втратити позначки в Safari (Chrome і Firefox так не роблять). Сайт, доданий на головний екран iPhone,
цього обмеження не має.

### Швидкість, коли відео багато

- Перша сторінка списку (50 найновіших відео) малюється одразу, решта довантажується фоном.
- Повторний візит показує все з кешу миттєво, а з YouTube бере лише першу сторінку, бо старіші відео
  не змінюються. Повний перезбір — раз на добу. Це береже і швидкість, і квоту YouTube API.
- Якщо YouTube не відповідає (чи нема інтернету), лишається копія з браузера. Архів (`archive.json`)
  підхоплюється, лише коли копії нема. Явний `state.json: doomsday` вмикає архів примусово.

### 🎲 Випадковий день

Кнопка над стіною (праворуч від назви місяця). Відкриває випадкове відео з усієї стіни, а якщо вибрано
тему — з відео цієї теми. День прокручується в поле зору й коротко підсвічується. Той самий день
двічі поспіль не випадає. Кнопка з'являється, коли відео щонайменше два.

### 🔗 Посилання на день

`taras.kyiv.ua/d/2026-09-30/` — окрема сторінка дня, яку генерує архів (див. нижче). Месенджери
(Telegram, Instagram, Facebook) показують гарне прев'ю: кадр дня, дату й назву, початок записки.
Людину сторінка одразу переносить на стіну до цього дня:
- на комп'ютері день підсвічується і відкривається відео;
- на телефоні день лише підсвічується (застосунок YouTube без дотику людини не відкриваємо).

У плеєрі на сайті є кнопка «🔗 Посилання на день»: на комп'ютері вона копіює адресу, на телефоні
відкриває системне меню «Поділитися». Якщо сторінку дня ще не згенеровано, адреса `/d/…/` однаково
працює через `404.html`, але прев'ю буде загальне.

### 👋 «З твого візиту»

Над стіною — тихий рядок для того, хто повертається: «З твого візиту — 3 нових дні · ▶ Дивитися підряд»,
праворуч «Переглянуто 23 з 37». Візит — заходи з перервами до 30 хвилин; «минулий» — останній захід перед
поточним. Нові — опубліковані після нього й ще не переглянуті. Усе в браузері глядача (ключ `lv`), без акаунтів.
- **Компʼютер:** нові дні грають підряд від найстарішого: коли відео скінчилось, вмикається наступне
  (для цього підвантажується YouTube IFrame API; не вийшло — гортаєш ›).
- **Телефон:** відкривається перший пропущений день у застосунку YouTube; рядок зменшується.
- Перший візит — рядка нема. Зіпсований запис у сховищі чи «майбутній» годинник — теж нема, без помилок.

### ⏭ Гортати дні в плеєрі

Під відео: «‹ 6 жовтня · 12 / 37 · 8 жовтня ›», стрілки ← → на клавіатурі, свайп убік на сенсорному екрані.
Над запискою — дата з днем тижня й назва. Гортання йде в межах того, звідки відкрили: уся стіна, вибрана тема,
сезон або «з твого візиту». Кожен відкритий день відмічається як переглянутий.

### 📱 Аркуш дня на телефоні

Дотик по кадру, як і раніше, одразу відкриває застосунок YouTube. Кнопка «⋯» у кутку дня відкриває аркуш:
кадр із кнопкою «▶ Дивитися в YouTube», дата, записка, теми, «🔗 Посилання на день», «📲 Картка для Stories»,
гортання ‹ › і свайп. Переглянутим день стає лише після «▶ Дивитися».

### 🖼 Картка дня

Кнопка в плеєрі (на компʼютері — «🖼 Картка дня», на телефоні — «📲 Картка для Stories») збирає вертикальну
картинку 1080×1920: кадр, розмитий фон із нього ж, дата з днем тижня, назва, рядки записки, 🌓 «Лови день» і адреса
дня. Верх і низ лишаються вільні — там у Stories кнопки Instagram. Опису у відео нема (звичайна справа) — кадр,
дата й назва стають посередині, без порожньої половини.
- **Телефон:** системне меню «Поділитися» (Instagram, Telegram…). Не вийшло — картинка зʼявляється в аркуші,
  її можна зберегти утриманням. Картку збираємо заздалегідь, щойно відкрито аркуш: iPhone дозволяє ділитися
  лише одразу після дотику.
- **Компʼютер:** файл `den-РРРР-ММ-ДД.jpg`.
- Кадр — з постера на сайті: `posters/ID-hd.jpg` (1280 px, його кладе архів на GitHub), інакше `posters/ID.jpg`.
  Мініатюру з YouTube напряму намалювати не можна, якщо YouTube не дозволить (CORS) — тоді картка з рамкою-заглушкою.

### 🎂 «Мій день»

Кнопка над стіною: вибираєш день і місяць (день народження, річниця) — і бачиш, що було в щоденнику того дня.
- Найсвіжіший рік; інші роки — кнопками під формою.
- Відео того дня нема — найближчий день із відео й пояснення.
- День ще не потрапив у щоденник — коли зʼявиться («Цей день буде тут 15 березня 2027»). 29 лютого — найближчий
  високосний рік; 31 квітня — «такого дня нема».
- **Компʼютер:** відкривається відео. **Телефон:** аркуш дня (картка «мій день» — у два дотики).
- Вибір памʼятає браузер (ключ `md`).

### 📱 Застосунок на головному екрані (PWA)

- **iPhone:** Safari → «Поділитися» → «На початковий екран».
- **Android / Chrome / Edge:** у шапці, праворуч від імені, з'являється «Встановити застосунок».
- Іконка — 🌓 з логотипа. Сторінка відкривається й без інтернету, з останньою збереженою стіною.
- На iPhone застосунок із головного екрана не потрапляє під 7-денне стирання сховища Safari,
  тож відмітки «переглянуто» не губляться.

## 🗄 Архів без комп'ютера (GitHub Actions)

`.github/workflows/archive.yml` раз на годину (о :17) запускає `tools/archive.mjs`. Скрипт:
- збирає з YouTube усі публічні відео фільмотеки й календаря (від їхнього `start`, без `exclude`) і сезонів;
- оновлює `archive.json`. Поля від локального скрипта (`v`, `d` тощо) зберігаються, оновлюються лише назва,
  постер і опис. Відео, що зникло з YouTube, з архіву не видаляється;
- кладе постери в `posters/ID.jpg` (~30 КБ, на власному домені), а для афіш і картки — великий кадр
  `posters/ID-hd.jpg` (поле `ph` в архіві);
- для фільмів записує тривалість (`dur`, секунди) — один раз, далі не перепитує;
- генерує сторінки днів `d/РРРР-ММ-ДД/` і `sitemap.xml`;
- тим самим запуском оновлює `fundraisers.json` — суми зборів із банок monobank (див. «Підтримка й збори»);
- комітить лише тоді, коли щось змінилось (`archive: оновлення …`), і просить GitHub Pages перезібрати сайт.

Дата дня рахується за київським часом. Запустити вручну: Actions → «Архів відео» → Run workflow.

**Що треба зробити один раз:**
1. Злити гілку в `main`: розклад GitHub запускає лише з гілки за замовчуванням.
2. (Бажано) Створити в Google Cloud окремий ключ YouTube Data API без обмеження за доменом
   (обмежити лише API → YouTube Data API v3). Додати його в Settings → Secrets and variables →
   Actions → New repository secret з назвою `YT_API_KEY`. Без нього скрипт бере ключ сайту з `index.html`
   і представляється як `taras.kyiv.ua`. Це працює, але окремий ключ надійніший.
3. Вимкнути локальний скрипт, який досі писав `archive.json`. Інакше обидва комітитимуть по черзі;
   конфлікту не буде (задача робить `pull --rebase`), але це зайве.

Локально: `node tools/archive.mjs` (змінні `YT_API_KEY`, `ARCHIVE_NO_POSTERS=1`, `ARCHIVE_OUT`, `ARCHIVE_FIXTURE` — для тестів).

## 💛 Підтримка й збори (підготовлено, вимкнено)

Блок `support` у `seasons.json`. Поки `"enabled": false`, глядачі не бачать нічого з цього, і сайт навіть не
запитує `fundraisers.json`. На `?check` усе видно на своєму місці з позначкою «вимкнено»:
так можна підготувати текст і подивитися, як це виглядатиме, до запуску.

Шапка лишається мінімальною — один ряд: іконка Instagram і поруч тихі посилання «● Збір: Назва ↗»
(і «Підтримати ↗», якщо увімкнено). Без кнопок, карток і закликів у плеєрі. Платної підписки на сайті нема.

```json
"support": {
  "enabled": false,
  "donate": { "enabled": false, "url": "", "label": "Підтримати", "about": "" },
  "fundraisers": [
    { "enabled": false, "id": "dron", "title": "Дрон для бригади", "about": "На що і навіщо — одним-двома реченнями.",
      "url": "https://send.monobank.ua/jar/…", "goal": 50000, "raised": 0, "until": "2026-12-31", "kind": "charity" }
  ]
}
```

Глядач бачить пункт, лише коли увімкнено **і** весь блок (`support.enabled`), **і** сам пункт (`enabled`).

- `fundraisers` — актуальні збори. Кожен — тихе посилання поруч з Instagram: «● Збір: Назва ↗». Воно веде
  одразу на банку. Під назвою — тонка шкала зібраного, якщо є ціль. `about` і суми видно підказкою при наведенні.
- `donate` — разова підтримка: Mono Base або банка. Таке саме тихе посилання «Підтримати ↗», без крапки.
  - `goal` і `raised` — гривні, числом.
  - `until` — останній день: після нього збір зникає сам.
  - `kind` — `charity` (благодійний) або `channel` (на канал).
  - `id` — якір. Посилання `taras.kyiv.ua/#f-dron` підсвічує збір у шапці червоним.

  Рекомендую тримати один, максимум два збори одночасно.

**Суми з банки — самі.** Якщо `url` збору — банка monobank (`send.monobank.ua/jar/…`), GitHub Action раз на годину
(`tools/fundraisers.mjs`, крок «Збори» в `archive.yml`) записує зібране у `fundraisers.json`. Сайт бере
звідти шкалу (запитує файл, лише коли на сторінці є збір із банкою), а до того — `raised` із `seasons.json`.
Цифри видно в підказці, на `?check` і в `/zbory` у бота. Без `goal` ціль теж береться з банки.
Два джерела:
- **секрет `MONO_TOKEN`** (необовʼязково) — особистий токен з api.monobank.ua. Це офіційний API, але працює лише
  для **твоїх** банок. Токен дає читати весь рахунок, тож він живе тільки в Settings → Secrets, ніколи не у файлах;
- **без токена** (або для чужої банки) — публічна сторінка банки. Це неофіційний спосіб: monobank може його змінити.
  Тоді лишаються останні відомі суми, а без них — `raised` із `seasons.json`. Сайт не ламається.

Після першого запуску звір на `?check` суму з тією, що в застосунку monobank: рядок «Збір» показує, звідки вона.
Mono Base так не вміє: публічного API для сторінки чи підписників нема, тож для Mono Base лише посилання.

**Збір можна додати й без редагування файлу — через бота** (наступний розділ).

**Як увімкнути вручну:** у `seasons.json` постав `"enabled": true` у потрібному пункті й у самому `support`, збережи,
відкрий `?check`.

Створюєш банку в застосунку monobank: назва, опис, ціль. Надсилаєш Гавриїлу посилання. За хвилину-дві в шапці сайту
поруч з Instagram з'являється тихе посилання «● Збір: Назва ↗»,
а Гавриїл відписує: «✅ Збір «Дрон для бригади» додано — taras.kyiv.ua/#f-dron-dlia-bryhady · 18 500 ₴ з 50 000 ₴».

```
/zbir https://send.monobank.ua/jar/…        додати: назва, опис і ціль — із самої банки
/zbir https://send.monobank.ua/jar/…        або зі своїми даними:
Дрон для бригади                             2-й рядок — назва, далі — опис
Збираємо на мавік для побратимів.
ціль 50000, до 31.12, благодійний            за бажання: ціль, останній день, вид (благодійний / на канал)
/zakryty                                     закрити (якщо відкритих кілька — бот перепитає, який)
/zakryty dron-dlia-bryhady                   …або за якорем, посиланням чи частиною назви
/zbory                                       що зараз на сайті й скільки зібрано
```

Усе можна й одним рядком: `/zbir <посилання> | Назва | ціль 60к | до 31 грудня`.
Повторний `/zbir` з тією самою банкою оновлює збір, а не дублює його; якір лишається той самий.

Як це влаштовано. Бот робить один запит до GitHub і нічого не розбирає сам. Задача «Збір із бота»
(`.github/workflows/fundraiser.yml`) запускає `tools/zbir.mjs`:
- він міняє `seasons.json` → `support.fundraisers` і вмикає `support.enabled`. «Підтримати», якого глядачі
  досі не бачили, так і лишається невидимим;
- комітить, просить GitHub Pages оновити сайт і відписує в Telegram.

Якщо в той самий момент комітить ще хтось (архів, ти вручну), задача бере свіжу версію й застосовує команду ще раз.

**Налаштування (один раз):**
1. Злити гілку в `main`: GitHub запускає таку задачу лише з гілки за замовчуванням.
2. Токен для бота: GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token.
   - Repository access — Only select repositories → `trs-hash/Films`.
   - Permissions → Actions — **Read and write**. Більше нічого: з таким токеном бот не може змінювати код.
   - Строк — до року; постав собі нагадування його оновити.
3. У боті:
   - змінні `FILMS_GITHUB_TOKEN` (той токен) і `FILMS_OWNER_IDS` — твій Telegram id (його покаже @userinfobot).
     **Команди приймаються лише від тебе:** інакше будь-хто, хто напише Гавриїлу, міг би поставити збір на сайт;
   - готовий код у `tools/gavriil/`: `films_zbir.py` (Python: python-telegram-bot чи aiogram) або `films-zbir.mjs`
     (Node: grammY чи Telegraf). Там і приклади підключення — по 4 рядки.
     Або віддай Claude Code у репозиторії бота готовий промт із `tools/gavriil/PROMPT.md`: він підключить усе сам,
     у стилі бота, з перевіркою власника й тестами. Якщо Гавриїл — асистент на LLM, промт описує й інструменти
     для звичайної мови («постав збір …»).
4. Щоб Гавриїл відписував результат: секрет репозиторію `TG_BOT_TOKEN` — токен Гавриїла від @BotFather
   (Settings → Secrets and variables → Actions). Без нього збір усе одно зʼявиться, просто без відповіді.
   Результат тоді видно в Actions → «Збір із бота».
5. (Необовʼязково) У @BotFather → /setcommands:
   `zbir - Додати збір на сайт`, `zakryty - Закрити збір`, `zbory - Збори на сайті`.

Без бота те саме можна зробити з телефона в застосунку GitHub: Actions → «Збір із бота» → Run workflow.
Або з компʼютера на сайті GitHub. У формі ті самі поля.

## Сезони (необов'язково)

Сезон — окремий блок під календарем: `weekly` (картки серій) або `daily` (своя стіна днів).
Порожній `seasons` означає, що блоку нема.

### Поля сезону

```json
{
  "seasons": [
    {
      "n": 1,
      "format": "weekly",
      "title": "Назва теми сезону",
      "about": "Кілька речень про тему.",
      "start": "2026-09-20",
      "end": "2026-12-20",
      "schedule": "Нова серія щонеділі",
      "playlist": "PLV5Ekm-F8nm4",
      "episodes": null,
      "support": ""
    }
  ]
}
```

- `format` — `weekly` (типово, картки серій) або `daily` (стіна днів, див. нижче).
- `n` — номер сезону; `start`/`end` — дати `РРРР-ММ-ДД`. За ними сайт сам вирішує:
  до старту — «Скоро» (анонс), між датами — «Зараз», після — «Завершено».
- `title` порожній → заголовком буде «Сезон N». `about` — опис теми (переноси рядків зберігаються).
- `playlist` — ID плейлиста сезону на YouTube. **Серії сезону = відео з цього плейлиста.**
  Приватні / заплановані відео не показуються, доки не стануть публічними.
- `episodes` — скільки серій заплановано (необовʼязково): тоді прогрес «Серій: 2 / 10»
  і пунктирне місце «наступна серія» зникне, коли всі вийдуть.
- `schedule` — вільний текст про ритм виходу. `support` — посилання «Підтримати сезон»
  (напр. mono-банка); порожнє → кнопки нема.
- Новий сезон = новий обʼєкт у масиві (порядок не важливий).

Опис відео на YouTube — це записка під плеєром (як і раніше): символ `№` (не «№5»)
позначає важливу серію червоною зірочкою, штамп `🕒 ГГ:ХХ ДД/ММ/РРРР` стає підписом.

У режимі `doomsday` серії беруться з `archive.json` і розкладаються по сезонах за датами `start…end`.

### Після кожної правки: taras.kyiv.ua/?check

Над сторінкою з'являється блок «Перевірка сайту». У ньому видно, що сайт зрозумів із `seasons.json`,
звідки взялися серії, скільки відео плейлиста сховано (приватні, заплановані, видалені) і що варто виправити.
Звичайні відвідувачі цього блоку не бачать.

Сайт не падає від типових ручних помилок: він їх виправляє або обходить і називає в `?check`.

| Помилка | Що робить сайт |
|---|---|
| зайва кома перед `}` або `]` | ігнорує її |
| `"n": "1"` рядком | читає як число |
| дата `20.09.2026` або `2026-9-20` | читає як `2026-09-20` |
| `end` раніше за `start`, дата, якої не існує | ігнорує `end` |
| немає `start` | вважає, що сезон уже йде |
| у `playlist` вставлено повне посилання на плейлист | бере з нього ID |
| неправильний ID плейлиста | порожній лише цей сезон, решта працює |
| `support` без `https://` | додає `https://` |
| невідоме поле (описка на кшталт `tittle`) | попереджає |
| `"enabled": "true"` чи `"так"` у лапках | читає як `true` |
| сума `"50 000 грн"`, `"1 500,50"`, `"50к"` | рахує в гривнях і просить писати числом |
| `fundraisers` — один обʼєкт, а не список | бере як список з одного збору |
| збір без `title`, `url`, з `javascript:` чи прикладом `XXXXXXXXXX` | не показує збір, пояснює в `?check` |
| пункт увімкнено, а `support.enabled` — ні | нічого не показує, пояснює в `?check` |
| два сезони з однаковим `n` | показує обидва |
| файл зіпсовано так, що JSON не читається | показує останню справну версію з кешу браузера, а в `?check` пише номер рядка з помилкою |

Новий відвідувач із зіпсованим файлом побачить «Не вдалось завантажити», тож після правки завжди відкривай `?check`.

## Щоденні відео: як повернутися через рік чи два

Щоденний формат уже вбудовано: це просто сезон з `"format": "daily"`. Сайт намалює його
«стіною днів», як старий календар, але всередині сезону, поряд з іншими:

```json
{
  "n": 3,
  "format": "daily",
  "title": "Назва щоденного сезону",
  "about": "Про що ці дні.",
  "start": "2028-01-01",
  "end": "2028-03-31",
  "schedule": "Нове відео щодня",
  "playlist": "PL…"
}
```

- Кожен прожитий день — клітинка з датою; день з відео — кадр (кілька відео за день ділять клітинку).
- Сьогодні, поки відео ще нема, — пунктирна клітинка «сьогодні»; майбутні дні не малюються.
- Тиждень без жодного відео стискається до тонкої смужки з датами, тож рідкі пропуски не роблять
  сторінку порожньою (саме через це колись і відмовились від календаря).
- Відкриті два останні місяці, давніші — під кнопкою «Раніше · N місяців»; завершений щоденний сезон
  згорнуто в «Календар сезону».
- Прогрес: «День 45 з 91». Переглянуте закреслюється хрестом (у щотижневих — смужка, як на YouTube).
- Можна вести одночасно щотижневий і щоденний сезони.
- `format` можна писати й українською: `щоденний` / `щотижневий`.

Перевірити, як це виглядатиме, до запуску: `node tests/qa.js D0` (скриншоти — у `tests/qa-shots/D*.png`).

## Швидкість

- Повторний візит малюється з кешу браузера ще до жодного запиту, а свіжі дані підтягуються одразу за ним.
- `seasons.json` і `state.json` запитуються ще в `<head>`, паралельно із завантаженням сторінки, і йдуть
  через кеш CDN (без `?cb=`; `?check` завжди бере свіжі).
- Запит до YouTube просить лише потрібні поля (`fields=`).
- Мініатюри з `srcset`: браузер бере 320–1280 px під розмір картки, але не менше ~90% її ширини в пікселях
  екрана. Велика картка на телефоні 3x бере 1280, на 2x і на ноутбуці — 640; маленькі картки — 320/480.
  Це правило перевірене заміром різкості і закріплене тестами `Q …`. Одразу вантажиться лише перший екран,
  решта — ліниво.
- Скелет на місці сезону з першого кадру: макет не стрибає.
