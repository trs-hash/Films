# Films — taras.kyiv.ua

Статичний сайт (GitHub Pages, домен у `CNAME`).

## Формат: сезони

Один сезон — одна велика тема, нова серія щотижня.

| Файл | Що це |
|---|---|
| `index.html` | Головна: сезони та їхні серії |
| `seasons.json` | Опис сезонів — **єдине, що треба редагувати руками** |
| `state.json` | Режим: `youtube` (жива стрічка з API) або `doomsday` (лише `archive.json`) |
| `archive.json` | Локальний архів (фолбек, коли YouTube недоступний) |
| `calendar.html` | Збережений старий макет — календарна «стіна днів» (окрема сторінка) |

### seasons.json

```json
{
  "seasons": [
    {
      "n": 1,
      "format": "weekly",
      "title": "Назва теми сезону",
      "about": "Кілька речень про тему.",
      "start": "2026-09-20",
      "end": "2026-12-20",
      "schedule": "Нова серія щонеділі",
      "playlist": "PLV5Ekm-F8nm4",
      "episodes": null,
      "support": ""
    }
  ]
}
```

- `format` — `weekly` (типово, картки серій) або `daily` (стіна днів, див. нижче).
- `n` — номер сезону; `start`/`end` — дати `РРРР-ММ-ДД`. За ними сайт сам вирішує:
  до старту — «Скоро» (анонс), між датами — «Зараз», після — «Завершено».
- `title` порожній → заголовком буде «Сезон N». `about` — опис теми (переноси рядків зберігаються).
- `playlist` — ID плейлиста сезону на YouTube. **Серії сезону = відео з цього плейлиста.**
  Приватні / заплановані відео не показуються, доки не стануть публічними.
- `episodes` — скільки серій заплановано (необовʼязково): тоді прогрес «Серій: 2 / 10»
  і пунктирне місце «наступна серія» зникне, коли всі вийдуть.
- `schedule` — вільний текст про ритм виходу. `support` — посилання «Підтримати сезон»
  (напр. mono-банка); порожнє → кнопки нема.
- Новий сезон = новий обʼєкт у масиві (порядок не важливий).

Опис відео на YouTube — це записка під плеєром (як і раніше): символ `№` (не «№5»)
позначає важливу серію червоною зірочкою, штамп `🕒 ГГ:ХХ ДД/ММ/РРРР` стає підписом.

У режимі `doomsday` серії беруться з `archive.json` і розкладаються по сезонах за датами `start…end`.

### Після кожної правки: taras.kyiv.ua/?check

Над сторінкою з'являється блок «Перевірка сайту». У ньому видно, що сайт зрозумів із `seasons.json`,
звідки взялися серії, скільки відео плейлиста сховано (приватні, заплановані, видалені) і що варто виправити.
Звичайні відвідувачі цього блоку не бачать.

Сайт не падає від типових ручних помилок: він їх виправляє або обходить і називає в `?check`.

| Помилка | Що робить сайт |
|---|---|
| зайва кома перед `}` або `]` | ігнорує її |
| `"n": "1"` рядком | читає як число |
| дата `20.09.2026` або `2026-9-20` | читає як `2026-09-20` |
| `end` раніше за `start`, дата, якої не існує | ігнорує `end` |
| немає `start` | вважає, що сезон уже йде |
| у `playlist` вставлено повне посилання на плейлист | бере з нього ID |
| неправильний ID плейлиста | порожній лише цей сезон, решта працює |
| `support` без `https://` | додає `https://` |
| невідоме поле (описка на кшталт `tittle`) | попереджає |
| два сезони з однаковим `n` | показує обидва |
| файл зіпсовано так, що JSON не читається | показує останню справну версію з кешу браузера, а в `?check` пише номер рядка з помилкою |

Новий відвідувач із зіпсованим файлом побачить «Не вдалось завантажити», тож після правки завжди відкривай `?check`.

## Щоденні відео: як повернутися через рік чи два

Щоденний формат уже вбудовано: це просто сезон з `"format": "daily"`. Сайт намалює його
«стіною днів», як старий календар, але всередині сезону, поряд з іншими:

```json
{
  "n": 3,
  "format": "daily",
  "title": "Назва щоденного сезону",
  "about": "Про що ці дні.",
  "start": "2028-01-01",
  "end": "2028-03-31",
  "schedule": "Нове відео щодня",
  "playlist": "PL…"
}
```

- Кожен прожитий день — клітинка з датою; день з відео — кадр (кілька відео за день ділять клітинку).
- Сьогодні, поки відео ще нема, — пунктирна клітинка «сьогодні»; майбутні дні не малюються.
- Тиждень без жодного відео стискається до тонкої смужки з датами, тож рідкі пропуски не роблять
  сторінку порожньою (саме через це колись і відмовились від календаря).
- Відкриті два останні місяці, давніші — під кнопкою «Раніше · N місяців»; завершений щоденний сезон
  згорнуто в «Календар сезону».
- Прогрес: «День 45 з 91». Переглянуте закреслюється хрестом (у щотижневих — смужка, як на YouTube).
- Можна вести одночасно щотижневий і щоденний сезони.
- `format` можна писати й українською: `щоденний` / `щотижневий`.

Перевірити, як це виглядатиме, до запуску: `node tests/qa.js D0` (скриншоти — у `tests/qa-shots/D*.png`).

## Повернутися до старого календаря як окремої сторінки

`calendar.html` — точна копія календарної головної (до 29.09.2026), доступна на `/calendar.html`.
Щоб повернути її на головну: скопіювати `calendar.html` поверх `index.html`
і прибрати з нього рядок `<meta name="robots" content="noindex">`.
Та сама версія є в історії git (коміт `b9cbb7d`).

## Швидкість

- Повторний візит малюється з кешу браузера ще до жодного запиту, а свіжі дані підтягуються одразу за ним.
- `seasons.json` і `state.json` запитуються ще в `<head>`, паралельно із завантаженням сторінки, і йдуть
  через кеш CDN (без `?cb=`; `?check` завжди бере свіжі).
- Запит до YouTube просить лише потрібні поля (`fields=`).
- Мініатюри з `srcset`: браузер бере 320–1280 px під розмір картки. Одразу вантажиться лише перший екран,
  решта — ліниво.
- Скелет на місці сезону з першого кадру: макет не стрибає.
